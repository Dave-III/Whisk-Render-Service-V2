# Whisk Render API

FastAPI service that accepts two MP4 uploads or Medal.tv clip links, renders a side-by-side MP4, and optionally uploads a completed render to YouTube.

## Runtime file layout

The backend stores transient files under `WHISK_DATA_DIR` (default `/tmp/whisk` in the container):

```text
$WHISK_DATA_DIR/
├── jobs/
│   └── <32-character-job-id>/
│       ├── manifest.json
│       ├── inputs/
│       │   ├── <random-id>.mp4
│       │   └── <random-id>.mp4
│       └── output/
│           └── <safe-name>_<job-id-prefix>.mp4
└── secrets/
    ├── client_secret.json
    └── token.pickle
```

`manifest.json` is UTF-8 JSON with `schema_version`, `job_id`, state, UTC timestamps, relative input names, and output media type/name. Secret files are materialized from Railway's existing base64 environment variables at container start and are excluded from the Docker build context and Git.

Completed and failed job folders are removed after `WHISK_JOB_RETENTION_HOURS` (default 2). A periodic janitor preserves active jobs. The Railway container filesystem is ephemeral; deploys and restarts can remove renders sooner. No persistent volume is attached.

## Local run

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
WHISK_DATA_DIR=./data uvicorn app.main:app --host 127.0.0.1 --port 8080
```

The backend requires Python 3.11, FFmpeg/ffprobe, and yt-dlp. Railway builds the `backend/` directory with its Dockerfile.

## Railway configuration

- Service root directory: `backend`
- Dockerfile: `Dockerfile`
- Container port: `8080` (Railway's `PORT` is honored)
- Health check: `GET /health`
- Keep `CLIENT_SECRET_B64` and `TOKEN_PICKLE_B64` set only in Railway Variables; their values are not needed by the rendering path.
- Optional variables: `WHISK_DATA_DIR`, `WHISK_JOB_RETENTION_HOURS`, and comma-separated `WHISK_ALLOWED_ORIGINS`. CORS credentials are disabled.

## API

- `GET /health` — health check.
- `POST /render` — multipart form with `clip1`/`clip2` MP4 files or `clip1_url`/`clip2_url` Medal.tv URLs, plus optional `auto_sync` and `output_name`.
- `GET /render-status` — current render progress, output filename, job ID, and download URL.
- `GET /download/{job_id}` — completed MP4.
- `POST /upload-youtube` — multipart `filename` and `title` for a completed output.

Upload and downloaded Medal clips are limited to 200 MB each. Output filenames are generated by the server; input paths and client filenames are never used as filesystem paths.
